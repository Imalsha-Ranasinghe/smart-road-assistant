================================================================================
  OVERVIEW
================================================================================

The system is a two-stage cascading inference pipeline built on top of a YOLOv8
object detector, with classical CV handling all post-detection analysis. No deep
learning is used after Stage 1 except the optional severity classifier.

Architecture pattern: Single detector → parallel analysers → lane-based merge

================================================================================
  ALL CV & IMAGE PROCESSING METHODS
================================================================================

  Method                          Where Used                  Purpose
  ------------------------------  --------------------------  ------------------
  Canny Edge Detection            Lane det. + Pothole CV      Road marking edges;
                                                              edge density score
  HoughLinesP                     Lane detection              Detect straight line
                                                              candidates from mask
  HLS Color Thresholding          Lane detection              Isolate white and
                                                              yellow lane markings
  HSV Color Thresholding          Traffic light color det.    Identify Red/Yellow/
                                                              Green pixels
  Polynomial fitting (polyfit)    Lane detection              Fit curved lane edges
                                                              from Hough candidates
  Vanishing Point computation     Lane detection              Geometric convergence
                                                              of left/right edges
  Trapezoid ROI masking           Lane detection              Restrict processing to
                                                              road-ahead region
  Slope filtering                 Lane detection              Reject near-horizontal
                                                              and near-vertical lines
  Brightness / V-channel thirds   Traffic light color det.    Position-based vote
                                                              (top=Red, mid=Yellow,
                                                              bot=Green)
  Laplacian variance              Frame extraction            Blur detection: discard
                                                              blurry video frames
  Perceptual Hash (pHash/DCT)     Frame extraction            Deduplication: discard
                                                              near-identical frames
  ByteTrack temporal tracking     Video pipeline              Stabilise detections
                                                              across frames
  Geometric lane-in-box test      Pothole filtering           Check if pothole is
                                                              inside lane corridor
  Lane relevance scoring          Traffic light filtering     Select traffic light
                                                              most relevant to ego
                                                              lane
  Laplacian-based depth scoring   Pothole CV scorer           Center vs border
                                                              brightness -> pit depth
  Texture scoring (std dev)       Pothole CV scorer           Intensity variation of
                                                              pothole surface
  Weather augmentation (Torch)    Training data prep          Rain, fog, night,
                                                              wet-road variants

================================================================================
  METHODOLOGY
================================================================================

------------------------------------------------------------------------
  Data Collection & Preparation
------------------------------------------------------------------------

Raw data comes from four public sources:
  - Chitholian pothole dataset     (Pascal VOC XML annotations)
  - Kaggle pothole dataset         (Pascal VOC XML annotations)
  - LISA traffic light dataset     (CSV annotations)
  - Bosch traffic light dataset    (YAML annotations)

All annotations are converted to YOLO bounding-box format
(normalized xc yc w h). The combined dataset is split 70/20/10
(train / val / test).

Severity classifier labels are auto-generated from bounding box area:
  box area < 3% of image   -> Low
  box area 3% -- 12%       -> Medium
  box area >= 12%          -> High

Video frames for the dashcam detector are extracted with two filters:
  1. Laplacian variance (threshold 60)  -- reject blurry frames
  2. pHash Hamming distance <= 6        -- reject near-duplicate frames

Training data is augmented with synthetic weather:
  Rain   : 700 random drops, 10-22 px vertical motion blur streak
  Fog    : alpha blend toward white (intensity 0.35 - 0.55)
  Night  : brightness multiply (0.18 - 0.30) + slight blue channel lift
  Wet    : saturation x 1.2-1.5, brightness x 0.75-0.90

All augmentation runs on GPU via PyTorch tensor operations.


------------------------------------------------------------------------
  Stage 1 -- Detection (YOLOv8s)
------------------------------------------------------------------------

A single-shot object detector finds both potholes and traffic lights in
one forward pass. Two weights files are maintained:

  detector_model.pt    : trained on static road imagery, 640 px input
  detector_dashcam.pt  : fine-tuned on dashcam perspective, 1280 px
                         input to resolve distant/small objects

Training details:
  Base weights  : yolov8s.pt (COCO pre-trained)
  Optimizer     : AdamW, lr0=0.005, cosine annealing
  AMP           : enabled (float16 for speed)
  Batch size    : auto-selected from GPU VRAM (e.g. 16 @ 640 on 8 GB)
  Mosaic aug    : disabled in last 10 epochs for fine detail recovery

In video mode, ByteTrack associates detections across frames using
IoU-based matching. A traffic light must appear in 3 consecutive frames
OR reach 50% confidence before triggering an alert, reducing flicker.


------------------------------------------------------------------------
  Stage 2a -- Pothole Severity (YOLOv8n-cls or Classical CV)
------------------------------------------------------------------------

Each pothole crop is analysed independently to determine severity and
distance.

CNN path (severity_model.pt):
  - YOLOv8n-cls (nano classification, ~2.6M parameters)
  - Input: crop resized to 128x128
  - Output: class index -> Low / Medium / High
  - Class order (alphabetical): High=0, Low=1, Medium=2

Classical CV path (fallback):
  1. Canny edges (50/150) -> edge density  (weight 0.40)
  2. Center vs border brightness -> depth score  (weight 0.35)
  3. Intensity std dev -> texture score  (weight 0.25)
  4. Weighted sum: >= 0.18 = High, >= 0.10 = Medium, else Low

A benchmark script (benchmark_severity.py) evaluates both methods on
the held-out test set and writes the winner to pipeline_config.yaml.

Distance estimation:
  box_bottom_y / frame_height > 0.80  ->  Very Close
  box_bottom_y / frame_height > 0.60  ->  Close
  box_bottom_y / frame_height > 0.40  ->  Medium
  otherwise                           ->  Far


------------------------------------------------------------------------
  Stage 2b -- Traffic Light Colour (Pure Classical CV)
------------------------------------------------------------------------

No deep learning model is used here. Each detected crop is classified
using two independent votes.

Vote 1: Position (brightness-based)
  - Resize crop to 48x144 (standard traffic light shape)
  - Divide into three equal horizontal thirds
      top third    -> Red position
      middle third -> Yellow position
      bottom third -> Green position
  - Compute mean V-channel (brightness) per third
  - Brightest third -> position vote

Vote 2: Colour (HSV thresholding)
  - Convert crop to HSV
  - Apply per-colour masks with saturation >= 80 AND value >= 80:
      Red    : hue  0-10  deg  (wrap-around also 160-180 deg)
      Yellow : hue 20-35  deg
      Green  : hue 40-80  deg
  - Count matched pixels per colour
  - Colour with most matched pixels -> colour vote

Confidence assignment:
  Both votes agree        -> confidence 1.0
  Only one vote available -> confidence 0.5
  Saturated pixels < 2%  -> Unknown, confidence 0.0
  (rejects dark/occluded lights and non-light objects)

False-positive rejection (before colour analysis):
  - Detector confidence >= 0.25
  - Box centre y <= 62% of frame height (mounted high, not tail lights)
  - Aspect ratio (height/width) >= 0.80 (tall objects, not wide signs)
  - Colour result != Unknown

Lane relevance scoring:
  Each surviving traffic light is scored:
    lane_score = 0.50 * nearness (box area / max area)
               + 0.30 * centrality to vanishing point corridor
               + 0.05 * mounting height
               + 0.15 * detector confidence

  The single highest-scoring light is marked lane_relevant = True.
  Only lane-relevant instructions are promoted to primary warnings.


------------------------------------------------------------------------
  Lane Detection (Pure Classical CV)
------------------------------------------------------------------------

No model. Entire pipeline is deterministic classical CV.

Step 1: Trapezoid ROI
  Masks out sky, roadside, and car hood.
  Defined by four image-relative parameters:
    LANE_HORIZON    = 0.58  (horizon line, 58% down from top)
    LANE_HOOD       = 0.93  (hood line, 93% down from top)
    TRAP_TOP_HALF   = 0.13  (half-width at horizon, fraction of frame width)
    TRAP_BOT_HALF   = 0.46  (half-width at hood)

Step 2: Lane marking extraction (HLS colour space)
  White markings: L in [165,255], S in [0,70]
  Yellow markings: H in [15,40], S >= 60, L >= 60

Step 3: Edge detection
  Grayscale -> Canny (low=60, high=150)

Step 4: Line detection
  Combined mask (colour OR edges) inside trapezoid ROI
  -> HoughLinesP(rho=1, theta=pi/180, threshold=40,
                 minLineLength=0.10*height, maxLineGap=60)

Step 5: Slope filtering and side assignment
  Keep lines with 0.35 <= |slope| <= 2.5
  Left-leaning (slope < 0, centre x < frame centre)
  Right-leaning (slope > 0, centre x > frame centre)

Step 6: Polynomial fitting x = f(y)
  Each line segment extrapolated to frame bottom for contact point.
  If >= 8 points AND height span >= 14% frame -> quadratic fit
  Otherwise -> linear fit

Step 7: Geometric validation (7 checks)
  1. Left edge x < frame_centre < right edge x at bottom
  2. Lane width at bottom in [0.18w, 0.95w]
  3. Top width <= 1.15 * bottom width (narrows toward horizon)
  4. Vanishing point x in [0.32w, 0.68w]
  5. Vanishing point y in [0.42h, 0.66h]
  6. Polyline stays within [-0.15w, 1.15w] horizontal bounds
  If any check fails -> fallback to fixed ROI corridor

Fallback ROI:
  Straight corridor from bottom centre converging to frame centre.
  Left:  38% of width (bottom) -> 50% (top)
  Right: 62% of width (bottom) -> 50% (top)

Output:
  left_poly, right_poly : list of (x,y) points including vanishing point
  assumed               : True if fallback, False if detected
  confident             : True if validated lane was found


------------------------------------------------------------------------
  Integration & Output
------------------------------------------------------------------------

Pothole filtering:
  The road-contact point of each pothole (bottom-centre of bounding box)
  is tested against the detected lane corridor using line parameterisation
  x_at(y). Potholes outside the corridor are deprioritised.

Traffic light selection:
  All traffic lights that pass false-positive rejection are scored.
  The single highest lane_score light is flagged as lane_relevant.
  Instructions for lane_relevant lights use assertive language
  (e.g. "STOP -- Red light. Do not proceed.").
  Non-lane-relevant lights use advisory language
  (e.g. "Red light detected in adjacent lane -- stay alert.").

Instruction generation matrix:
  Potholes:
    High   x Very Close -> "BRAKE NOW! Severe pothole directly ahead."
    High   x Close      -> "Reduce speed immediately. Severe pothole ahead."
    High   x Medium     -> "Slow down. Large pothole in your path."
    High   x Far        -> "Hazard ahead -- prepare to slow down."
    Medium x Very Close -> "Avoid this lane if safe. Moderate pothole."
    Medium x Close      -> "Slow down. Moderate pothole ahead."
    ...

  Traffic lights (lane_relevant=True):
    Red    -> "STOP -- Red light. Do not proceed."
    Yellow -> "SLOW DOWN -- Yellow light. Prepare to stop."
    Green  -> "PROCEED -- Green light. Check for crossing hazards."

  Traffic lights (lane_relevant=False):
    Red    -> "Red light detected in adjacent lane -- stay alert."
    ...
