──────────────────────────────────────────────────────────────────────────────
TECHNIQUE 1 — LAPLACIAN OPERATOR FOR BLUR DETECTION
──────────────────────────────────────────────────────────────────────────────

What it is (CV/IP concept):
  The Laplacian is a second-order derivative operator used in image processing
  to measure the rate of change of intensity gradients. It is defined as:

      ∇²f = ∂²f/∂x² + ∂²f/∂y²

  A sharp image has strong, high-frequency edges — the Laplacian response
  at edge pixels is large. A blurry image has softened edges — the Laplacian
  response is weak everywhere. The variance of the Laplacian across all pixels
  summarises this sharpness into a single scalar.

How we used it:
  We compute the Laplacian of each greyscale frame and take its pixel variance:
      cv2.Laplacian(gray, cv2.CV_64F).var()
  Frames below a threshold of 60.0 are rejected as too blurry to annotate.

Why it matters for CV:
  Motion blur during dashcam recording causes pothole bounding box boundaries
  to be undefined — the pothole edge literally does not exist as a detectable
  feature in the image. Training the detector on such frames injects label
  noise: the model is shown a box around a region that has no clear boundary,
  which degrades detection precision.

Result:
  Blurry frames (common during road bumps and sharp turns) are automatically
  rejected before annotation, giving a cleaner training dataset.

──────────────────────────────────────────────────────────────────────────────
TECHNIQUE 2 — PERCEPTUAL HASHING (DCT-BASED IMAGE SIMILARITY)
──────────────────────────────────────────────────────────────────────────────

What it is (CV/IP concept):
  Perceptual hashing (pHash) is a compact image descriptor based on the
  Discrete Cosine Transform (DCT) — the same transform used in JPEG compression.
  It represents the dominant low-frequency visual structure of an image as a
  64-bit binary fingerprint.

How it works:
  1. Resize the frame to 32×32 pixels (removes fine detail, keeps structure)
  2. Apply 2D DCT — transforms pixel space to frequency space
  3. Keep only the top-left 8×8 DCT coefficients (lowest frequencies)
  4. Binarize: bit = 1 if coefficient > median, else 0
  → Result: a 64-bit hash fingerprint

  Two images are "visually similar" if their Hamming distance (number of
  differing bits) is ≤ 6 out of 64.

      small = cv2.resize(gray, (32, 32))
      dct   = cv2.dct(small)[:8, :8]
      hash  = dct > np.median(dct)         ← 64-bit binary descriptor

How we used it:
  Each kept frame's hash is compared against the last 30 kept frames.
  If Hamming distance ≤ 6, the frame is a near-duplicate and is discarded.

Why it matters for CV:
  At 30 FPS, consecutive frames are nearly identical. Including duplicates
  introduces data redundancy bias — the model sees the same visual pattern
  hundreds of times, causing it to overfit to that specific scene while
  underperforming on diverse real-world footage.

Result:
  A dashcam trip that produces 108,000 raw frames is reduced to ~2,400
  visually diverse, sharp frames ready for annotation.

──────────────────────────────────────────────────────────────────────────────
TECHNIQUE 3 — BOUNDING BOX COORDINATE NORMALISATION (Geometric Transform)
──────────────────────────────────────────────────────────────────────────────

What it is (CV/IP concept):
  In image processing, coordinate normalisation maps pixel-space coordinates
  to a scale-invariant representation. All four source datasets store
  bounding boxes in absolute pixel coordinates (xmin, ymin, xmax, ymax).
  YOLO requires a different representation: centre point + dimensions,
  normalised to image size.

The transformation (applied to every bounding box):
      x_center = (xmin + xmax) / (2 × image_width)
      y_center = (ymin + ymax) / (2 × image_height)
      width    = (xmax  − xmin) / image_width
      height   = (ymax  − ymin) / image_height

  All values fall in [0, 1] — completely resolution-independent.

Why it matters for CV:
  - Images in the dataset range from 480×360 to 1920×1080 pixels
  - A normalised annotation is valid regardless of the image resolution
  - During training, YOLOv8 resizes all images to 640×640 — normalised coords
    scale correctly with no modification to the label file

──────────────────────────────────────────────────────────────────────────────
TECHNIQUE 4 — ROI (REGION OF INTEREST) EXTRACTION WITH PADDING
──────────────────────────────────────────────────────────────────────────────

What it is (CV/IP concept):
  Region of Interest (ROI) extraction is a fundamental CV operation: crop a
  meaningful sub-region from a full image to isolate a specific object for
  further analysis. Boundary padding ensures the ROI includes context pixels
  around the object edge.

How we used it:
  For the Stage 2a severity classifier, each pothole bounding box is extracted
  from the original image with 10-pixel padding on all sides:

      x1 = max(xmin − 10, 0)          ← clamp to image boundary
      y1 = max(ymin − 10, 0)
      x2 = min(xmax + 10, img_width)
      y2 = min(ymax + 10, img_height)
      crop = image[y1:y2, x1:x2]

  Each crop is then resized to 128×128 pixels for the classifier input.

Why it matters for CV:
  The full image contains road, sky, vehicles — irrelevant background for
  severity assessment. ROI extraction focuses the classifier on the pothole
  region only, removing background noise. The 10px padding retains the
  pothole edge and immediate surrounding texture, which carry information
  about depth and damage extent.

──────────────────────────────────────────────────────────────────────────────
TECHNIQUE 5 — SPATIAL AUTO-LABELLING (Area Ratio Heuristic)
──────────────────────────────────────────────────────────────────────────────

What it is (CV/IP concept):
  This uses spatial analysis of the detected region's geometry as a proxy
  for object severity — a form of image-based measurement. The underlying
  CV principle is that apparent object size in an image is inversely
  proportional to distance, and directly proportional to physical size.

Rule applied to every pothole bounding box:
      ratio = box_area / image_area
              = (width_px × height_px) / (img_width × img_height)

      ratio < 0.03   → Low    (small/distant pothole)
      0.03 – 0.12    → Medium
      ≥ 0.12         → High   (large/close pothole — high danger)

Why it matters for CV:
  A large bounding box means the pothole occupies more of the frame →
  it is either physically large or very close to the camera → greater
  immediate danger. This heuristic derives a semantic label (severity)
  purely from geometric measurement, without any human annotation effort.
  It is equivalent to a simple rule-based classifier operating in the
  spatial domain.

──────────────────────────────────────────────────────────────────────────────
TECHNIQUE 6 — RAIN SIMULATION USING 1D CONVOLUTION
──────────────────────────────────────────────────────────────────────────────

What it is (CV/IP concept):
  Convolution is the most fundamental operation in image processing.
  Here, a 1D vertical averaging kernel simulates motion blur — the same
  principle used in motion blur filters in any image editing tool.

How it works:
  Step 1: Create a sparse mask of 700 random bright pixels (simulating
          rain drop positions).
  Step 2: Apply a vertical 1D convolution kernel of length 10–22 pixels
          (randomly chosen per image):
              kernel = [1/L, 1/L, ..., 1/L]  (L entries, vertical direction)
          This stretches each bright dot into a vertical streak.
  Step 3: Blend the rain layer onto the image:
              result = image × 0.88 + rain_streaks × 0.55

  This is equivalent to a motion blur filter applied directionally, then
  composited using alpha blending.

Why it matters for CV:
  Rain creates visual occlusion — it reduces object contrast, adds texture
  noise, and partially obscures the road surface. A model that never trains
  on rain images will lose confidence on wet-day dashcam footage. The
  convolution approach is computationally efficient (GPU tensor op) compared
  to drawing individual lines with a CPU loop.

──────────────────────────────────────────────────────────────────────────────
TECHNIQUE 7 — FOG SIMULATION USING ALPHA BLENDING
──────────────────────────────────────────────────────────────────────────────

What it is (CV/IP concept):
  Alpha blending (linear interpolation between two images) is a standard
  compositing technique in image processing. Fog reduces visibility by
  scattering light — modelled as blending the scene with a uniform white layer.

Formula:
      result = image × (1 − α) + white × α
      where α = uniform(0.35, 0.55)

  This is the standard image compositing over operation with a flat white
  background. At α = 0.5, the image and fog contribute equally.

Why it matters for CV:
  Fog globally reduces image contrast and suppresses high-frequency detail
  (edges, textures). Since pothole detection relies on edge response and
  texture cues, training on foggy images forces the model to develop
  more robust, low-frequency features.

──────────────────────────────────────────────────────────────────────────────
TECHNIQUE 8 — NIGHT SIMULATION USING GAMMA / POINT OPERATION
──────────────────────────────────────────────────────────────────────────────

What it is (CV/IP concept):
  A point operation (or intensity mapping) transforms each pixel independently:
      output(x,y) = f(input(x,y))
  Gamma correction is a specific point operation: output = input^γ.
  Reducing brightness by multiplication is equivalent to linear gamma < 1.

How we applied it:
      result = image × brightness   (brightness = uniform(0.18, 0.30))
      result[blue_channel] += 0.04  ← slight blue cast

  The blue channel addition simulates the colour temperature of LED streetlights
  (which have a cool blue tint compared to daylight).

Why it matters for CV:
  Night dashcam footage has fundamentally different contrast distribution
  from daytime images. Shadows are deeper, highlights (headlights, streetlights)
  create severe contrast ratios, and road texture is less visible. Training
  without night images means the model has only learned daylight feature
  distributions.

──────────────────────────────────────────────────────────────────────────────
TECHNIQUE 9 — WET ROAD SIMULATION USING COLOUR SPACE MANIPULATION
──────────────────────────────────────────────────────────────────────────────

What it is (CV/IP concept):
  Saturation adjustment operates in the HSV (Hue-Saturation-Value) colour
  space. Saturation controls the vividness of colours — a wet road has
  higher saturation because water on the surface enhances colour reflection.
  Brightness adjustment operates on the V channel of HSV.

How we applied it:
      saturation × uniform(1.2, 1.5)    ← increase colour vividness
      brightness × uniform(0.75, 0.90)  ← slightly reduce overall brightness

  Internally: torchvision converts RGB → HSV, scales S and V channels, and
  converts back to RGB.

Why it matters for CV:
  Wet roads have high reflectivity — they can produce specular highlights
  that visually resemble pothole shadows. Training on wet-road images teaches
  the model to distinguish genuine potholes from wet-surface reflections,
  reducing false positives.

──────────────────────────────────────────────────────────────────────────────
TECHNIQUE 10 — GPU-ACCELERATED TENSOR PROCESSING
──────────────────────────────────────────────────────────────────────────────

What it is (CV/IP concept):
  Modern deep learning frameworks (PyTorch) represent images as floating-point
  tensors on the GPU. All arithmetic operations (convolution, blending, gamma)
  run as massively parallel GPU operations — the same hardware used for
  neural network training.

How we used it:
  Images are converted: BGR uint8 (OpenCV) → float32 RGB tensor (PyTorch):
      t = torch.from_numpy(rgb).permute(2,0,1).float().div(255.0).to(DEVICE)
  All weather effects operate on these tensors directly.
  Output is converted back: tensor → BGR uint8 for disk storage.

Why it matters:
  Processing 26,000 training images × 3 copies = 78,000 augmented files.
  GPU tensor ops are 50–100× faster than equivalent CPU pixel loops.
  Additionally, multiprocessing (CPU cores − 2 workers) parallelises the
  file I/O, saturating both the GPU and disk simultaneously.

  import sys
  sys.path.insert(0, '../src')
  import cv2, random, torch, numpy as np, matplotlib.pyplot as plt
  from pathlib import Path
  from augment import add_rain, add_fog, add_night, add_wet_road, img_to_tensor, tensor_to_img

  BASE_DIR = Path('..').resolve()
  val_imgs = sorted((BASE_DIR/'data/processed/detector_yolo/images/val').glob('*'))[:5]
  effects  = [('Original', lambda t: t), ('Rain', add_rain),
              ('Fog', add_fog), ('Night', add_night), ('Wet Road', add_wet_road)]

  fig, axes = plt.subplots(5, 5, figsize=(16, 16))
  for col, img_path in enumerate(val_imgs):
      frame = cv2.imread(str(img_path))
      t     = img_to_tensor(frame)
      for row, (name, fn) in enumerate(effects):
          result = tensor_to_img(fn(t.clone()))
          axes[row][col].imshow(cv2.cvtColor(result, cv2.COLOR_BGR2RGB))
          axes[row][col].axis('off')
          if col == 0:
              axes[row][col].set_ylabel(name, fontsize=12, fontweight='bold')
  plt.suptitle('Data Augmentation — Weather Effects', fontsize=14, fontweight='bold')
  plt.tight_layout()
  plt.savefig('augmentation_grid.png', dpi=150, bbox_inches='tight')
  plt.show()


================================================================================
  QUICK CODE TO VISUALISE BLUR DETECTION FOR YOUR SLIDES
  (Figure A — proves Laplacian blur filter works)
================================================================================

  import cv2, matplotlib.pyplot as plt, numpy as np
  from pathlib import Path

  # Pick one sharp and one blurry frame (or use any two images)
  BASE_DIR   = Path('..').resolve()
  imgs       = sorted((BASE_DIR/'data/raw/dashcam_frames').glob('*.jpg'))[:20]

  scores     = [(cv2.Laplacian(cv2.imread(str(p), cv2.IMREAD_GRAYSCALE),
                               cv2.CV_64F).var(), p) for p in imgs]
  sharp_path = max(scores)[1]
  blurry_path= min(scores)[1]

  fig, axes  = plt.subplots(2, 3, figsize=(14, 8))
  for row, (path, label) in enumerate([(sharp_path,'KEPT'), (blurry_path,'REJECTED')]):
      img  = cv2.imread(str(path))
      gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
      lap  = cv2.Laplacian(gray, cv2.CV_64F)
      score= lap.var()
      axes[row][0].imshow(cv2.cvtColor(img, cv2.COLOR_BGR2RGB))
      axes[row][0].set_title(f'{label}  —  Original', fontweight='bold')
      axes[row][1].imshow(gray, cmap='gray')
      axes[row][1].set_title('Greyscale')
      axes[row][2].imshow(np.abs(lap), cmap='hot')
      axes[row][2].set_title(f'Laplacian  (variance = {score:.1f})')
      for ax in axes[row]: ax.axis('off')
  plt.suptitle('Blur Detection via Laplacian Variance', fontsize=13, fontweight='bold')
  plt.tight_layout()
  plt.savefig('blur_detection.png', dpi=150, bbox_inches='tight')
  plt.show()

3 ANSWERS FOR AUDIENCE QUESTIONS
────────────────────────────────────────────────────────────────────────────────

  "Why did you filter blurry frames?"
    "A blurry frame has no detectable edge. Training on it teaches the model
     to draw boxes around nothing."

  "Why did you augment the data?"
    "Road hazards don't disappear when it rains. Our model shouldn't either."

  "Why didn't you manually label severity?"
    "A pothole that fills 15% of your windscreen is more urgent than one
     that covers 2%. Geometry does the labelling for us."

-- Figure: blur_detection.png (for Slide 2) --

  import sys; sys.path.insert(0, '../src')
  import cv2, numpy as np, matplotlib.pyplot as plt
  from pathlib import Path

  frames_dir = Path('..').resolve() / 'data/raw/dashcam_frames'
  imgs = sorted(frames_dir.glob('*.jpg'))[:30]
  scores = [(cv2.Laplacian(cv2.imread(str(p), 0), cv2.CV_64F).var(), p)
            for p in imgs]
  sharp  = max(scores)[1]
  blurry = min(scores)[1]

  fig, axes = plt.subplots(2, 3, figsize=(14, 8))
  for row, (path, label, score) in enumerate([
      (sharp,  'KEPT',     max(scores)[0]),
      (blurry, 'REJECTED', min(scores)[0])
  ]):
      img  = cv2.imread(str(path))
      gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
      lap  = np.abs(cv2.Laplacian(gray, cv2.CV_64F))
      axes[row][0].imshow(cv2.cvtColor(img, cv2.COLOR_BGR2RGB))
      axes[row][0].set_title(f'{label} — Original', fontweight='bold')
      axes[row][1].imshow(gray, cmap='gray')
      axes[row][1].set_title('Greyscale')
      axes[row][2].imshow(lap, cmap='hot')
      axes[row][2].set_title(f'Laplacian  (var = {score:.0f})')
      for ax in axes[row]: ax.axis('off')
  plt.suptitle('Laplacian Blur Detection', fontsize=14, fontweight='bold')
  plt.tight_layout()
  plt.savefig('blur_detection.png', dpi=150, bbox_inches='tight')
  plt.show()

-- Figure: augmentation_grid.png (for Slide 4) --

  import sys; sys.path.insert(0, '../src')
  import cv2, matplotlib.pyplot as plt
  from pathlib import Path
  from augment import add_rain, add_fog, add_night, add_wet_road
  from augment import img_to_tensor, tensor_to_img

  imgs    = sorted((Path('..').resolve() /
                    'data/processed/detector_yolo/images/val').glob('*.jpg'))[:5]
  effects = [('Original', lambda t: t), ('Rain',     add_rain),
             ('Fog',      add_fog),     ('Night',    add_night),
             ('Wet Road', add_wet_road)]

  fig, axes = plt.subplots(5, 5, figsize=(16, 14))
  for col, p in enumerate(imgs):
      t = img_to_tensor(cv2.imread(str(p)))
      for row, (label, fn) in enumerate(effects):
          out = tensor_to_img(fn(t.clone()))
          axes[row][col].imshow(cv2.cvtColor(out, cv2.COLOR_BGR2RGB))
          axes[row][col].axis('off')
          if col == 0:
              axes[row][col].set_ylabel(label, fontsize=12, fontweight='bold',
                                        rotation=0, labelpad=55, va='center')
  plt.suptitle('Weather Augmentation — Data Preprocessing',
               fontsize=14, fontweight='bold')
  plt.tight_layout()
  plt.savefig('augmentation_grid.png', dpi=150, bbox_inches='tight')
  plt.show()
